# Runtime SDK foundations — #184 / #464

`symbiote-runtime-sdk` separates `AgentRuntimeAdapter` (agent/session loop) from `InferenceProviderAdapter` (model requests). It consumes canonical Dispatch, Role, Runtime Profile and enforcement records. No adapter method completes a canonical Task.

Qualification distinguishes native ownership from external full harnesses, transport from integration tier, granular capabilities from enforcement strength, and observed facts from unknown/unsupported features. Native profiles need no external installation. An embedded external harness cannot validate as native ownership. A tier label never supplies a missing capability or proves certification.

Qualification checks adapter/installation/profile revision/model, Host eligibility, version/platform proof bindings and expiry, mandatory compiled controls, named tools/skills and context bounds. Observed or emulated controls cannot satisfy preventive enforcement. The Host must authenticate referenced proof artifacts; SDK metadata cannot prove its own truth.

`DeclaredRuntime` is the input form of a descriptor, for the operator of a Host that has no probe yet: it names the runtime identity (`adapter`, `installation`, `profile`, `model`, `runtime`, `owner`, `transport`, `tier`, `platform`) and asserts the facts (declared capabilities, controls with their mechanism, tools, skills, context limits) — and nothing about who observed them. `DeclaredRuntime::observe(host, at)` produces the `RuntimeDescriptor` the rest of the SDK consumes: the Host supplies its own identity, the evidence artifact and a one-hour window, so the observation is the Host's and the facts are the operator's. A capability the declaration omits is absent rather than supported, a declared control weaker than the profile's minimum refuses, and a declaration is bound to the profile identity it names. This is the same posture as Host enforcement claims, not a substitute for sandbox-observed evidence.

`PreparedLaunch` is data-only. Authorization rechecks freshness, calls a trusted `ActivationJournal` to persist the exact Dispatch and descriptor, and checks the receipt before producing a nonserializable `LaunchPermit`. Adapters must revalidate the permit immediately before activation. Rust visibility is not a sandbox against code in the trusted process. The callback is an SDK interface, not the SQLite adapter's production activation transaction. Durable fencing/outbox recovery and actual supervision remain downstream obligations. The metadata daemon exposes no launch operation in this batch.

`projection` names where each workforce fact has to be *carried* for a runtime to act under it — the Workforce Protocol, the Role's operating contract, the Task Contract and context handoff, skills, tools and MCP, native permissions and sandbox, hooks and events, plugins and extensions, the worker's own environment, secret references, verification/exit signals and cleanup — and reports each surface against the runtime's own declared carriers. The demand is the contract's own: a surface demands the controls the contract claims over it, each control carried on exactly one surface, plus the capabilities the binding's own resources require, so nothing a runtime advertises becomes a requirement. A runtime with no carrier for a demanded fact is named rather than omitted: a control the descriptor does not list, a capability declared unsupported, one not yet established and one the descriptor never mentions are four different facts. A control the runtime declares *weaker* than the contract's claim is recorded as a degradation with both strengths retained, so the projection never smooths observation into prevention. A projection carries the canonical identities and revisions it references — protocol, role contract, task contract, role, binding, task, root, stream — and no content of theirs: an adapter that restated the protocol or the task brief inside a projection would be a second copy of the contract. `ContractProjection::reconcile` compares the runtime's own handshake after launch with what was delivered, in one direction: a report may narrow but never widen (a stronger or incomparable strength, a carrier the projection found missing, unsupported or unknown, a carrier the surface does not demand, or a malformed mechanism refuses with the typed error), a weaker report is named as weaker, a silent surface stays unreported, and no handshake field can carry canonical completion. `AgentRuntimeAdapter::projection` and `handshake` are hooks over the descriptor the Host already holds: neither launches anything, and qualification plus the Host's activation transaction remain the only gate. `binding_surfaces` reads the same surfaces one step earlier: a binding and the Host's observation of a runtime, with no Task Contract compiled and no dispatch identity to name. Its demand is the binding's own — the enforcement minimums its policy declares, the capabilities that policy requires, and the tools and skills it names, which the dispatch boundary requires the same way — so the instruction, hook, extension and environment carriers, which a *compiled contract* is what places, are the projection's demand rather than the binding's. `BindingSurfaces::withheld` uses the same rule as `ContractProjection::withheld` and answers the same question for the pre-contract step: which places does this runtime carry nothing for. A control carried weaker than the binding's minimum is a degradation with both strengths and is not withheld — whether a minimum is met is qualification's refusal, one fact with one owner. Real adapters filling these surfaces with real carriers — protocol files a harness reads, mechanisms a sandbox enforces, MCP registrations, real handshakes — remain open under #184.

`conformance` is the suite every adapter runs, published beside the projections it reads rather than kept as one adapter's private test: `RULES` names each rule, `run_conformance` runs them over the dispatches the caller supplies, and `ConformanceReport` publishes each rule's outcome by name with the two matrices a pack hands a reader — one row per capability the module places, one row per control, each carrying the descriptor's own declaration, whether any dispatch demanded it, and whether every place that did reports it carried. A failure names the rule and the declared fact that moved: the descriptor's own validity, the evidence a declared carrier names, the dispatch and runtime identity a projection reports, the surfaces it covers and their order, the carriers it reads, the claims it reads, and whether two reads of one dispatch agree — so the comparison is partitioned into failure vocabularies rather than reported as one whole-projection mismatch. What the suite cannot decide is stated rather than implied. It reads a descriptor and the adapter's own projection of a dispatch, all pure and in-process: it launches no session, observes no process and authenticates no evidence, because launching needs a permit only authorization mints and authenticating proof is the Host's before any of this metadata is trusted. It decides no eligibility either: a demand the declaration never answers is a row in the matrix — declared nowhere, demanded, not realized — and the refusal stays qualification's, because a suite that refused it here would be a second owner of the decision. The window a descriptor's evidence spans is read and the clock it is compared against is not, for the same reason. A production run is a run against actual abstract work, so the dispatches are the caller's and the suite invents no task, role or binding to project. No production adapter implements `AgentRuntimeAdapter` yet, so the suite is the protocol a pack runs rather than a gate that already has subjects. The rules, by the names a failure carries, are `descriptor_identity_is_valid`, `every_declared_capability_names_evidence_of_its_own`, `every_declared_control_names_evidence_of_its_own`, `the_adapters_projection_names_the_runtime_its_own_descriptor_names`, `every_projection_covers_every_surface_in_the_modules_order`, `every_demanded_capability_is_carried_exactly_as_it_is_declared`, `every_demanded_control_is_read_at_the_strength_the_descriptor_declares` and `reading_the_same_dispatch_twice_gives_the_same_projection`; a case holds this document to that list, so a rule renamed without its document fails rather than leaving a document that describes a suite nobody runs.

`dossier` is the record a Harness Pack publishes behind its claims: one `ConformanceRun` per upstream version and platform the pack was actually run against, carrying the suite's own outcome, the suite's own capability and enforcement matrices, and the surfaces that run carried nothing for. It is built from runs rather than from records: `CompatibilityDossier::publish` takes the runtimes themselves and the abstract work to run them over, as `PackRun`, evaluates the suite there, and reads the upstream version, the adapter version, the platform, the tier and the driver from the descriptor it evaluated — so a pack has no parameter to publish a version it was not run against, a matrix its run did not read, or an outcome its run did not have, and a dossier that arrives over a wire is a reader's input rather than a construction path. Its refusals are named: `RulesFailed`, `NoDispatches`, `NoRuns`, `MoreThanOnePack` and `TheSameVersionTwice`. A dossier states the shape it speaks in its own `DOSSIER_SCHEMA_VERSION`; a published rule row is a name, an outcome and a failure, with the suite's prose for a rule left in the SDK that runs it, so a reworded rule cannot make a published dossier read as a different rule; and `CompatibilityDossier::run`, `versions` and `hold` are the only ways into what a pack publishes, so a version absent from `versions` is a version the dossier says nothing about, and a holding can only name a run the record itself carries. `CompatibilityDossier::publishes` is the one comparison of a pack's identity, read both by a Host choosing which installed file to serve and by `hold` refusing a foreign one, so the choice and the check cannot disagree about which file is whose.

`CompatibilityDossier::hold` is the reader's side, and the only side that reads a parsed record: nothing in a document somebody wrote can be believed, and the facts it states about outcomes are exactly the facts a reader cannot observe. Given the runtime a reader actually holds — a `DeclaredRuntime`, the form a Host holds its operator's assertions in — it serves the record only when it is that pack's (`AnotherPack`), speaks the `DOSSIER_SCHEMA_VERSION` this crate speaks (`UnknownShape`), names no other pack in any of its runs (`TheRunNamesAnotherPack`), carries no rule row under a name the suite does not publish (`UnknownRules`), has each version and platform in exactly one run (`TheSameRunTwice`), shows an outcome that held for every rule the suite runs (`ARuleDidNotHold`), carries the two matrices this suite publishes row for row (`TheMatricesAreNotTheSuites`, which names which matrix), has a run over real work (`TheRunReadNoDispatch`), and has one for the upstream version and platform that runtime declares (`NoRun`) made with that runtime's own adapter version (`AnotherAdapterVersion`). A rule with no row, a row under another name, a row reporting a failure, a row claiming an outcome beside a failure and a second row beside a held one are one absence of evidence — two rows cannot be averaged into one outcome — and the refusal names every rule it found. What is compared is the record's shape and the outcomes it reports: what a row *says* about a run is the pack's claim, because a record carries each dispatch's summary rather than the work the suite read, so those values are served as published rather than read as observed. A `DossierHolding` names the run and the declaration it was made from instead of copying either, and `HoldError::name` is the stable refusal name for a boundary that has to name the refusal without repeating the document.

Holding a record is neither qualification nor authentication, and a tier is a label: a held record says the pack passed this suite at this version on this platform, and the Host still decides eligibility and still verifies proof. A dossier decides nothing — the Host still qualifies a runtime against its declaration and still authenticates proof. A case holds this document to these names as well.

[Runtime events](runtime-events.md) supply bounded immutable identity, gap/replay handling, tool lifecycle and cancellation uncertainty. Worker completion and exit code zero never grant canonical completion. [Provider contracts](providers.md) separate native API and harness authentication/billing and require explicit model capability support. Unknown usage remains unknown; local unauthenticated endpoints require exact Host-approved policy.

Reference adapters/journal in tests are in-memory conformance fixtures. They prove qualification/ordering, not real PTY execution, durable activation or OpenAI/Codex integration. The generic PTY fixture lacks required controls and is rejected; the structured fixture receives a permit only with matching fixture evidence. Real transports, installation/authentication/probe lifecycles, profile reconciliation, upstream dossiers, process boundaries, native model/tool loop, Codex App Server and cross-runtime end-to-end proof remain open under #184/#464 and integration owners. Unsupported behavior must never be replaced with simulated success.
